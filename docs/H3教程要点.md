# 教程要点（秋叶 ComfyUI 教程 BV15Hap6uEvY，17 集）

> 研究对象：`【秋叶ComfyUI教程】教你用8G显存流畅跑AI漫剧…`（含 MiniMaxH3 影视创作全流程）
> 与我们的流水线一一对应：**04 角色资产图生图 / 08 双采多参生视频 / 09 剧本创作 /
> 10 资产建立 / 11 视频生成 / 13 第一部AI漫剧 / 16 影视创作 / 17 解决油腻·美学参考**

## 一、结论：我们的流程错在哪

| 教程的做法 | 我们原来的做法 | 后果 |
|---|---|---|
| **一个片段里包含多个镜头**，切点写在提示词的时间戳里 | 一句台词切一刀，两秒一个镜头 | 看着晕、不和谐、没有美感 |
| **角色资产图**：先做一张全身照，再用图片编辑派生出三视图/四视图 | 正面/侧面/四分之三/背面**分开生成** | 四个面板其实是四个人 → 人物必然漂 |
| **资产库 = 角色 + 场景 + 道具** | 只有角色和场景 | 戒指、合同这类贯穿道具会变形 |
| **每个镜头写清三件事**：谁在画面里 / 在什么地方 / 在做什么 | 写了但没强制 | 模型自己编，人物和场景跑掉 |
| **视频生成 = 参考图 + 提示词 + 分辨率 + 时长**，双采只是加速版 | 只给了首帧 | 身份只能靠猜，每镜都不一样 |
| **二采 = 快；官流单采 = 质量**；关掉加速 LoRA 时间翻倍但质量更好 | 一直用 4 步 turbo LoRA | 快但糙 |
| **英文提示词**（模型对英文理解更到位） | 英文 ✓ | 已经对了 |

## 二、已经落到流水线里的

- [x] **片段制**：分镜表的一行 = 一个 6~15 秒的片段，段内可以有多个镜头，
      切点由提示词里的 `At 00:0X.000, the camera cuts to ...` 决定
      （`shot_duration_range: [6.0, 15.0]`）
- [x] **一集 5 分钟**：`episode_duration: 300`，`max_episode_seconds: 330`，
      每集最多 90 个片段
- [x] **角色资产图 = 一张母图派生**：先生成正面全身照，其余视图用图片编辑从它派生
      （`character.py`：第一个视图是母图，后面的带母图做参考图）
- [x] **四视图**（正面/侧面/四分之三/背面，`ref_views`）
- [x] **每个视频都带参考图**：角色资产图 + 场景图 + 本镜首帧，最多 5 个参考图槽位
      （R2V 的 `ref_image_0..4`）
- [x] **参考图不齐就不抽卡**：缺三视图、缺场景图、缺首帧 → 这一镜不生成视频并报错
      （`refs.missing_references`）
- [x] **提示词逐张点名参考图**：谁的身份、哪个房间、哪一帧是起点，
      官方 R2V 写法（`subject_definitions` / `retention_analysis`）
- [x] **画面 + 人声 + 音效一次出**（ref2va，H3 自己说话，嘴型天生对齐）
- [x] **旁白只是字幕卡**，不进 `<d>` 标签，不被念出来
- [x] **镜头描述三要素**：谁 / 在哪 / 在做什么

## 三、还没做的（按性价比排）

1. **道具资产库**：把贯穿全剧的道具（戒指、合同、病历）也做成资产图，一样给出参考
2. **双采（二采）**：一采潜空间 → 放大 → 二采（去噪 0.7），官方说这是**加速**方案，
   质量以官流单采为准；我们现在是单采 4 步 turbo，出终稿时应该**关掉 turbo LoRA**、
   步数提到 20~25
3. **融合模型**：`minimax_h3_*_mixed_int4_int8_convrot`（FL+RE 合并）就是老师说的"融合模型"，
   "既有参考又有美学"，还解决人物油腻——**这个权重我们已经下好了**（给 3090 备的），
   5080 上也可以用
4. **风格 LoRA**：画风统一用 LoRA 锁（老师推荐 Krea2 + 风格 LoRA）
5. **负面提示词**按画风各出一套（写实类的负面词很关键）
6. **四宫格角色参考图**：侧脸不好看时改用"正面全身+正面半身+侧面+背面"的四宫格，
   而且右下角的小脸要裁掉，免得模型参考错

## 四、速度参考（老师 5060Ti 16G 实测）

- 8 秒的片段 ≈ 10 分钟
- 14 秒的片段 ≈ 20 分钟
- 关掉加速 LoRA 时间翻倍，质量更好
- 我们有 5080 + 2×3090，出终稿时建议：3090 跑双采/长片段，5080 跑出图和终稿

## 四之二、我们在自己机器上量出来的（2026-10-31，单张 3090）

**老师的工作流就在 3090 那台机器上**：`/data/comfyui/user/default/workflows/H3/`
（已拷到 `rounds/teacher_h3/`）。八个：参考生视频-角色一致 / 多帧锚点参考 /
图生视频 / 首尾帧长视频续接 / 文生视频-{快速预览,高速高质,高清成品} / 视频放大2K。

**关键：文生视频那三个的差别不是分辨率，是子图里的一个开关（`value`）**：

| 工作流 | 分辨率 | 开关 | 步数 | 说明 |
|---|---|---|---|---|
| 快速预览 | 0.4 MP | True | **6** | 只看画面 |
| **高速高质** | 0.98 MP | True | **6** | **我们该用的档** |
| 高清成品 | 0.98 MP | False | **20** | 终稿档（关掉 turbo LoRA 的"官流单采"） |
| 参考生视频-角色一致 | 1344×768 | — | **20** | 我们的参考生视频版，步数是 20 不是 4 |

**我们自己的单次生成工作流，四个档的实测（单张 3090，10.1 秒 / 243 帧）**：

| 档位 | 耗时 | 参考图跟得住吗 |
|---|---|---|
| 768×1344 / 8 步 / `ref_image_size=max` | **19.3 分钟** | ✓ 白婚纱、头纱、红毯、动作全对 |
| 768×1344 / 6 步（=老师的"高速高质"） | **14.7 分钟** | ✓ 同样跟得住 |
| 576×1024 / 8 步 | **7.4 分钟** | ✓ 身份和构图不丢，脸略软 |
| 480×832 / 8 步 | **4.0 分钟** | ⚠ 脸明显糊（头纱的珠子都没了） |

**分辨率是最大的杠杆**（代价随像素超线性增长：1.03MP→19.3 分钟，0.4MP→4.0 分钟），
比步数更值钱。老师的"视频放大2K"工作流用 **SeedVR2** 放大，**3090 的容器里没装任何
custom node**，所以低分辨率+放大的路子暂时走不通。

**4 步 turbo LoRA 不行**：参考图依从性≈0（婚纱从白变香槟、房间从 LED 屏变红幕布）。
至少 6 步，最好 8 步。
