# 迭代记录：10 轮短剧全链路测试

每一轮都是：**换一个新剧本 → 跑完整流水线 → 自动质检 → 找出问题 → 改代码 → 下一轮**。

## 目录

| 路径 | 内容 |
|---|---|
| `scripts/roundNN.txt` | 该轮的剧本（1 分钟以内的短小剧本，每轮一个题材） |
| `logs/roundNN.log` | 该轮流水线的完整日志 |
| `reports/roundNN.qa.json` | 该轮的质检报告（机器可读） |
| `../projects/轮次NN_*` | 该轮的**全部素材**：角色定妆照、场景参考图、每镜首帧、每段视频、逐句配音、字幕文件、成片、FCPXML |
| `总报告.md` | 10 轮的汇总与逐轮问题（`summary.py` 自动生成） |

跑一轮：

```bash
venv\Scripts\python.exe round.py --round 3
```

连跑多轮（每轮一个独立进程，轮次之间的修改会在下一轮生效）：

```bash
venv\Scripts\python.exe rounds\loop.py 4 10
```

看所有轮次的对比：

```bash
venv\Scripts\python.exe rounds\summary.py
```

## 质检查什么（`qa.py`）

**画面**
- 从成片抽 16 帧，测相对锐度（拉普拉斯方差除以亮度，暗场景才不会假阳性）
- 亮度/饱和度的镜头间差异（按分位数，避开特写与淡入淡出）
- 调色是否真的收窄了镜头差异（调色前后逐镜配对比较）
- 素材是否够长到填满它的槽位（不够就是冻帧）
- 台词是不是切在镜头边界上（不是就说明画面停在上一句的镜头上）
- **景别**：连续三个同景别要报出来（那叫证件照连播）；第一镜不能是特写
- **节奏**：平均一刀多少秒、开场第一个镜头多长、前 3 秒切了几刀
- **钩子**：第一句台词是不是在 3 秒内出现、有没有太长

**配音**
- 每句对白都必须有音频；旁白/字幕卡**不许**被朗读
- 每句的时长是否合理（太快=截断，太短=没念完）
- 每个角色的基频与过零率（音色辨识度）：两个角色不能听起来一样
- 情绪标签的解析（"冷笑（愤怒）"这类复合标签要落到真实情绪上）

**混音**
- 成片响度、真峰、黑帧
- 对白与音乐垫底的响度差（音乐不能盖住人声，也不能听不见）
- 完整性与长度：成片必须和时间线一样长，一分钟上限

**字幕**
- 条数对不对、一条几行、会不会超出画面宽度
- 时间轴有没有进位错误（3.996 必须写成 4.00 而不是 3.100）
- 字幕之间会不会重叠、会不会比配音先消失
- **位置**：字幕必须落在画面下方三分之一（曾经落在 60% 高度，正好挡住脸）

**专业交接**
- FCPXML 能不能打开：引用的素材是否都存在、主轨有没有断裂、音轨是否齐全

**叙事 / 合规**
- 说话的人是不是在画面里（按角色整体比例判定，单个反应镜头是正常剪辑）
- 可能过不了审的措辞（2026 年平台审"整剧立意"，敏感词会下架）

## 工具

```bash
# 拉片：量参考片的剪辑节奏，写进分镜提示词
dj ref-rhythm 参考片.mp4 --apply

# 让多模态模型看片：它能看出机器测不出来的毛病
# （比如"这句台词配的是另一个人的特写"）
dj review 轮次09_09

# 逐镜检查人脸漂移：把每个镜头的首帧和末帧并排给模型看
dj drift 轮次09_09

# 一集成片的进度与体检
dj status 项目名
```

### 看片工具用的什么

`review` 与 `drift` 都用 MiniMax-M3.1-Flash 的多模态接口（`chat/completions`
+ `image_url` 的 data URI）。两个坑：

- 纯 http(s) 的图片地址会 400，**必须**用 `data:image/jpeg;base64,...`
- M3 是推理模型，`max_tokens` 至少要 16000：给 4000 的话思考过程就把额度
  用光了，`content` 是空的，`finish_reason` 是 `length`

## 第十一轮：声音回到画面上

这一轮只做一件事：**把一个视频反复迭代**（第 9 轮「退婚」），把"声音游离于
画面外"这个观感问题解决掉。

### 病灶

让多模态模型看片，它给的分数是：总分 68，画面 74 / **音画关系 61** / 节奏 64
/ 表演 66，最严重的一条是：

> 字幕说话人与画面嘴型疑似错位——把苏念的台词放在正在动嘴的顾承舟特写上

### 三个真凶

| # | 病灶 | 证据 | 改法 |
|---|---|---|---|
| 1 | **时间线把台词抢走了** | 单镜对白超过 3.5 秒时，代码把尾部台词"没收"塞给别的镜头，于是整场台词错位一格 | 分镜的分配是**最终决定**，长度上限只用来安置无家可归的台词 |
| 2 | **提示词没说谁在说** | H3 提示词只说"角色说话时的表演"，没说这一镜谁开口、另一个人的嘴不许动 | 提示词点名说话人，并要求其余人**闭着嘴只是听**；系统提示里也写一遍 |
| 3 | **各阶段各算各的时间线** | `promptgen` 建时间线时没算句间留白，和合成阶段的不一致 → 提示词要的台词和实际配音的镜头对不上 | 全流水线统一走 `ctx.timeline(ep)` |

顺带修掉的：

- **对话顺序被打乱**（第 5 轮：「册封沈氏为贵妃」排在「太后懿旨」前面）
- **有台词没落到任何镜头** → 场景比镜头长 → 所有台词被拉伸 → 字幕和配音对不上
- **补位的台词塞进了靠前的镜头**（回答跑到问题前面）
- **竖版角色照污染出图**：`_fit_refs` 里 `iw` 未定义 → FLUX 3 跟着 768×1024 出图
  → 竖版视频被裁成横幅 → **这就是"画面开始扭曲"的来源**（质检加了画幅检查）
- **配乐提示词一次调用失败就静默丢掉音乐**（计数照加，肉眼看不出来）→ 重试 + 兜底模板
- **过长的镜头**（一句 6 秒）→ 分镜阶段自动拆成两个镜头，景别也换

### 口型对齐（MuseTalk）

上面三条解决的是"谁在说"，解决不了"嘴型和词对不上"。为此接了 MuseTalk：
用录好的音频重画嘴。新增阶段 `lipsync`，跑在 `visual` 之后、`compose` 之前。

- 代码与权重在 `E:\musetalk`（权重经 hf-mirror 镜像下载，HF 本体在这台机器上不通）
- 官方实现要 mmcv（要对着 torch 编译）和 librosa（要旧 numpy），这里都绕开了：
  人脸框改用仓库自带的检测器，wav 改用 soundfile
- 打开方式：`config/default.yaml` 里 `compose.lipsync: true`

## 这一轮迭代改掉的东西

按发现顺序：

1. **一次显存溢出打死了整集** —— ComfyUI OOM 后会卸载全部模型，所以出图/出视频现在会自动重试；ComfyUI 启动加了 `--vram-headroom 1.5`
2. **音乐垫底盖住了人声** —— 垫底不再用固定增益，改为按每集实测对白与音乐的最响处，把差距稳定在 12 LU
3. **调色在放大差异** —— ffmpeg 的 `eq=contrast` 是绕中灰缩放的，暗镜头会被压死；改用饱和度+白平衡+最后统一曝光，亮度差从 29 降到 6
4. **多场景的配音互相覆盖** —— 每个场景的配音轨都写同一个文件名，第二个场景把第一个覆盖了，第 2 轮因此丢了 22 秒对白（成片 18 秒而不是 30.75 秒）
5. **画面比音频短，mux 取短的那条** —— 冻帧补帧量从固定 2 秒改成按素材实际长度算
6. **字幕时间轴进位错误** —— `3.996` 被写成 `3.100`，字幕早消失 0.9 秒、下一句早出现 0.9 秒
7. **台词和镜头各走各的** —— 分镜现在声明自己承载哪几句台词，镜头长度由台词决定，切点落在台词边界上
8. **画面先拍、配音后录，两份时间线对不上** —— 阶段顺序改成先录音再拍
9. **H3 自己念台词** —— 提示词里让 H3 描述角色说话，它就合成出乱码语音压在配音上；现在只描述表情和动作
10. **复合情绪标签查不到映射** —— "冷笑（愤怒）"这类标签以前等于没有情绪，台词被平读
11. **一个文件锁打死一整集** —— 每句配音都有重试，音频改成原子写
12. **一集能跑到 69 秒** —— 剧本预算上限改成一分钟
13. **镜头之间人物站位乱跳** —— 下一镜的提示词会带上上一镜结束时的状态
14. **字幕跑到了画面中间** —— 边距是按 1080 高写的，用在 544 高的画面上就成了 60% 高度
15. **说话没有口型** —— H3 提示词不再描述发声动作，嘴就一直闭着
16. **H3 的乱码语音压在配音上** —— 每个场景改用一段"无人无声"的纯配乐镜头做垫底，镜头自己的原生音整条弃用
17. **只有台词和音乐，缺了音效层** —— 配乐镜头现在同时带上本场关键动作的声音（开门、电话、雨）
18. **AI 生成没有标注** —— 成片左上角烧上"本片画面与声音由AI生成"（备案号在 `config/default.yaml` 的 `filing_number` 填）
19. **出图比例与成片比例各写各的** —— 出图尺寸现在跟着成片尺寸走，换成竖屏不会把人脸裁掉
