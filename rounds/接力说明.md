# 接力说明：下一次开机做什么

> 2026-10-31 状态。上一集"出片了"，其实**没出片**：33 个片段一个视频都没有，
> 成片是 33 张静帧做的 Ken Burns。三处根因都已修（见下"第三之二"）。
> 这一轮同时把"一集 5 分钟 / 一行分镜 = 6~15 秒片段"落到了代码里。

## 〇、这一轮最重要的三件事

| 现象 | 根因 | 现在的做法 |
|---|---|---|
| **成片是幻灯片，一段视频都没有** | 场景名（"酒店宴会厅·主舞台"）和资产名（"五星级酒店婚礼宴会厅"）对不上 → 参考图闸门认为"没有房间参考图" → **每一段都"不抽卡"** | 场景名改成解析式匹配（`refs.find_location`：精确→归一→子串→字符重合≥0.6）；闸门放行后正常出片 |
| **阶段报"33 镜成功"其实 0 个视频** | `visual` 的计数器把"出图成功"也算成了"镜头成功" | 计数分开：`images_ok` / `videos_ok`；`precheck` 现在把"只有静帧没有视频"判为**错误**并拦下合成 |
| **一集只有 102 秒，片段只有 3 秒** | 时间线让**台词长度**决定镜头长度（一句短台词 → 3 秒的镜头），而 H3 提示词里写的是 7.4 秒的戏 → 片段和它自己的说明书对不上 | 镜头长度=导演给的片段长度（6~15 秒），台词塞进去；一集的片段按 `episode_duration` 缩放到 5 分钟 |

### 第三之二、片段长度的规矩（这一轮定的）

```
一行分镜 = 一个 6~15 秒的片段（段内 2~4 个镜头，切点写在提示词里）
镜头长度 = 片段长度（分镜表给的），台词塞进片段里，不是反过来
一集片段数 ≈ episode_duration / 10.5（5 分钟 ≈ 29 个片段）
但台词少的场不硬撑：片段数 ≤ 台词能承载的 2.5 倍
```

改动落在 `dramakit/pipeline/base.py`（`build_timeline`）和
`dramakit/pipeline/storyboard.py`（`_fit_durations` + 片段预算）。

### 第三之三、参考图清单的三处对齐（重要）

提示词里 `<Picture 1..N>` 的编号 = 上传顺序 = 清单顺序，三者必须一致：

- **首帧的槽位要提前预留**：写提示词时首帧还没出，之前首帧被省掉了 →
  提示词说"Picture 3 是房间"，实际第 4 张是首帧，谁也没说它是什么。
  现在 `picture_plan` 永远给首帧留槽（`refs.py`）。
- **场景名要能对上资产名**（上一条）。
- **出图也要带房间参考图**（`visual._ref_images` 之前也是字面匹配 → 房间从没进过首帧）。

## 〇之二、3090 的速度（实测，别再猜）

单张 3090（int8_convrot + nvfp4 文本编码器），768×1344：

| 片段 | 8 步 | 4 步（turbo LoRA 的设计步数） |
|---|---|---|
| 10.1 秒（243 帧） | **20 分钟** | 10 分钟 |
| 5.2 秒（124 帧） | 6.0 分钟 | ~3 分钟 |
| 1.6 秒（39 帧） | 1.2 分钟 | ~40 秒 |

一集 5 分钟（33 段 × 9.85 秒）= **约 11 小时**（8 步）。片段越短越便宜
（每帧的代价随帧数超线性增长），但一集的**总帧数**才是大头。

日志里每步 134 秒，**一半时间是模型换入**（dynamic VRAM loading），显存只占 16.5/24GB。
那台机器现在**只剩一张卡**（`nvidia-smi -L` 一张，`lspci` 一条），第二个实例起不来，
所以并发=1。

## 〇之二之二、参考图：模型到底吃哪几张（这一轮最贵的发现）

**1. 4 步 turbo LoRA 会把参考图"吃掉"**。同一个提示词、同一个种子：

| 步数 | 结果 |
|---|---|
| 4 步 | 婚纱从白变香槟金、房间从 LED 屏变红幕布、脸也换了 —— **参考图基本没起作用** |
| 8 步 | 白婚纱、白西装、头纱、红毯、宾客、站位全部对上 ✓ |
| 12/16 步 | 和 8 步差别不大 |

**2. `<Picture 1>` 才是模型跟的那张**。提示词写"这张是首帧"但把它排在最后 → 没用；
把首帧排第一 → 构图跟住了。所以清单顺序必须是：**首帧 → 角色三视图（说话人第一个）→ 场景图**。

**3. `ref_image_size` 要用 `max`**，不是默认的 `match`：
`match` 把参考图缩到出图尺寸（身份保真度低），`max` 保留 2048 短边（"最佳身份保真"）。
我们实测 8 步下两者**一样快**（0.7 分钟/22 帧），所以直接用 `max`。

**4. 上传名必须唯一**。每个角色的三视图都叫 `sheet.jpg`，用文件名上传 → 全传到服务器
同一个地址 → **后传的把先传的盖掉**，同一个任务里两个槽位拿到同一张脸。
现在用**内容指纹**做前缀（`edac016aba_shot_sh-xxx.png`）。

**5. 没用的槽位要从任务里删掉**。工作流里 5 个槽位，没填满的还留着 `placeholder.png`
（服务器上没有这个文件）→ 节点报错、模型吃到一张坏图。现在把没填的槽位从
`ref_images` 里删掉，节点就不会执行。

**6. 空槽位的教训**：参考图要**逐张点名**（谁的身份、哪个房间、哪一帧是起点），
提示词的编号 = 上传顺序 = 清单顺序，三者必须一致。

## 〇之三、这轮的质检口径改动（`qa.py`）

| 检查 | 原来 | 现在 |
|---|---|---|
| `voice_signature` | 取整段最亮的一帧算基频 → 所有角色都是 222Hz → 每对角色都被报"太像" | 取各帧基频的**中位数**；"太像"改成相对差 <6% 且过零率差 <10%；另加**精确检查**：两个角色同一音色同一音高语速 |
| `prompt_without_line` | 用时间线窗口找台词 → 算到隔壁镜头的台词 | 用**分镜表自己的分配**（`shot.line_indices`），并要求台词原文出现在提示词里 |
| `dialogue_missing` | 数成片混音的响度跳变 → 音乐盖住，数字没意义 | 原生音频路径改成**逐片段查有没有人声**（`has_voice`）；非原生路径保留原口径 |
| precheck | 只有静帧也放行 | 视频模式下"只有静帧没有视频"= **错误**，拦下合成 |

## 〇、这一轮的硬规矩（2026-10-31 用户定的）

| | |
|---|---|
| 画幅 | **16:9 横屏**（之前是 9:16 竖屏） |
| 分辨率 | **1024×576**（出图、视频、成片都是；还在测试优化阶段，不做高分辨率） |
| 参考图 | **必须有一张面部满屏照**——脸在全身照里太小，模型锁不住脸 |

对应改动：

- `config/default.yaml`：`comfyui.width/height` = 1024/576、`video_width/height` = 1024/576、
  `compose.width/height` = 1024/576、`characters.ref_width/height` = 1024/576
- `characters.ref_views` = `[front, face, side, three_quarter, back]`：**新增 face 视图**
  （从正面全身派生，脸占满画面，用作身份锚点）
- `refs.picture_plan`：人物的参考图用**面部满屏照**（没有才退回四视拼版）；
  清单顺序固定为 **首帧 → 人物面部特写 → 场景**
- `visual._ref_images`（出图）：同样优先用面部满屏照
- `t2i_flux3_klein_ref.json`：参考图槽位从 2 个扩到 **4 个**（3 个角色 + 房间；
  原来两个角色就把房间挤掉了）
- `promptgen._reference_jobs`：按新清单逐张点名（首帧=构图、面部=身份、场景=环境）

**为什么脸部特写是单开一张而不是拼进四宫格**：拼版里脸只占五分之一，
模型看到的是一张小脸；单独一张占满画面，身份才锁得住。

## 〇之四之二、参考图与提示词的三条硬规矩（这一轮总结）

1. **`<Picture N>` 的编号 = 上传顺序 = 清单顺序**，三者必须一致；首帧排第一（模型只跟第一张）。
2. **上传名必须唯一**：每个角色的三视图都叫 `sheet.jpg`，用文件名上传会互相覆盖 → 用内容指纹做前缀。
3. **没用到的槽位要从任务里删掉**：留着 `placeholder.png`（服务器上没有）会让模型吃到一张坏图。

## 〇之五、这一轮踩到的"提示词自己骗自己"

- **模型会漏台词**：3/33 段的提示词里没有它承载的台词（有一段连 `<d>` 都没有）。
  现在代码兜底：不属于这一镜的 `<d>` 标签会被拿掉，漏掉的会按时间点补回去。
- **模型会把字幕卡当台词**：「第二集·暴雨」被塞进 `<d>` 念了出来 → 过滤要用 `is_narration`（含 caption 和"旁白"说话人），不能只看 kind。
- **质检的台词数法和流水线不一致**：质检把 caption 算成台词 → 索引整体错位一格 → 一堆假警报。现在统一用 `is_narration`。

## 一、这一轮的结论（都已验证）

| 问题 | 根因 | 现在的做法 |
|---|---|---|
| 画面扭曲 | `_fit_refs` 里 `iw` 未定义 → 竖版角色照污染出图 → 竖版视频被裁成横幅 | 已修；出图 768×1344、成片 1080×1920 |
| 声音和画面对不上 | 时间线把台词从它自己的镜头"抢走"塞给别的镜头，整场错位一格 | 分镜的分配是最终决定；长度上限只安置无家可归的台词 |
| 说话人不在画面里 | H3 提示词没说这一镜谁开口 | 提示词点名说话人，其余人闭着嘴只是听 |
| 台词被拉伸 | 句尾的留白算进了台词本身 | 台词保持录音的长度；留白是镜头末尾的空 |
| 各阶段时间线不一致 | `promptgen` 建的时间线没算留白 | 全流水线走 `ctx.timeline(ep)` |
| 画面里出现黄色文字 | 场景描述里带着引号里的台词，模型把它画成了字幕 | 画面描述里去掉引号内容；旁白只出声不显示 |
| 桌子在木纹和大理石之间跳 | 场景描述写的是 "warm wood **and** dark marble table" | 场景描述只许写一种；提示词说参考图是唯一标准 |
| **人声是乱码** | 一直在用 **fl2va**（首尾帧）模型，它不会说话 | 换 **ref2va**（参考图）模型，它能说中文 |

## 二、最重要的发现：`ref2va` 能说话

MiniMax H3 有两个开源 transformer：

- `fl2va`（首/末帧 → 视频+音频）：**人声出来是乱码**。我们以前只能把它的音频丢掉、
  用单独录的音做画外音——这就是"声音飘在画面外"的由来。
- `ref2va`（参考图/视频/音频 → 视频+音频）：**人声是清楚的中文**。

实测（whisper-small 转写）：

```
ref2va + <d>[zh-CN]我想清楚了。</d>   ->  「我想清楚了」   ✓
fl2va  + <d>[zh-CN]我想清楚了。</d>   ->  乱码
```

而且 ref2va 能吃**参考音频**：把我们的配音录音当 `<Audio 1>` 喂进去，
H3 就用那个音色说我们的话（官方原话："Audio carries timbre, not words"）。
所以现在是：**画面 + 嘴型 + 人声 + 音效一次出**，嘴和声音是同一次生成的。

## 三之二、看完成片之后的最后一轮改动

看完成片（竖屏那版），最大的问题是**节奏太赶**：一句一镜，每句都切，
台词之间只有 0.35 秒的停顿，而且 H3 说得比录音慢，**话没说完就被镜头尾砍掉**。

改了这些（还没跑过）：

| 改什么 | 从 | 到 |
|---|---|---|
| 句间留白 | 0.35s | **0.5s** |
| 单镜对白上限 | 3.5s | **4.5s**（一镜可以带两句短的） |
| 镜头时长区间 | 2~4s | **2.5~6s** |
| 分镜规则 | "通常 1 句" | "**不要一句一镜**，两句之间留半秒" |
| H3 提示词的时间轴 | 按录音长度 | 录音长度 ×1.15 + 0.15，并写明"**在这段时间里说完**" |
| 质检的节奏阈值 | 平均 >3.5s 报 | 平均 >4.0s 报；两句话的镜头允许 6.5s |

下次开机跑这一轮，然后重点看三件事：
1. 台词还有没有被砍掉半句（转写每镜，跟剧本对）
2. 句与句之间的停顿是不是有"人味"了
3. 切点是不是少了（目标 12~18 刀/分，不是 20~30）

## 四之二、已经验证过的
